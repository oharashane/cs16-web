The network settings, in plain words

Counter-Strike is a conversation. The server tells your game where everyone is, many times a second; your game tells the server what you did, many times a second. These four settings are how often and how much. None of them changes the game itself, only how it feels — and how it feels depends on the machine and the connection, which is why they are here to try rather than fixed.

Updates from the server (cl_updaterate)

How many times a second the server sends you the world. More is smoother and more up to date, and costs bandwidth and a little CPU; fewer is lighter, and each update carries more that has to be smoothed over. The server allows 20 to 101. As shipped: 100.

Commands to the server (cl_cmdrate)

How many times a second your game sends what you did — moved, aimed, fired. More is more precise; it should be at least your frame rate, and there is no point above it. The engine allows up to 100 (the old game's config said 105, which this engine rounds down).

Interpolation (ex_interp)

Your game draws other players slightly in the past, so that between two updates their movement is smooth rather than jumping. This is how far in the past, in seconds. Auto means one update's worth — at 100 updates a second that is 10 ms, at 20 it is 50 ms — and is right for most people. A bigger number is smoother when updates are late or lost, and everyone is that much further behind where they really are. 0.1 was the game's old default and is why the old game felt the way it did.

Bandwidth (rate)

The most the server may send you, in bytes a second. A hundred updates a second of a busy round needs 30,000 or more; below that the server holds back updates ("choke"), which feels like lag though the connection is fine. The old game shipped with 20,000, and the server used to cap everyone at 25,000 — that cap is 100,000 now. There is no cost to setting this high on a home network.

Sound lead (_snd_mixahead)

Not network at all, but it lives here because it is the other thing you can feel. The engine mixes sound this far ahead of time, in seconds, so that a slow frame does not leave a gap in the audio; the browser's own output buffer adds about another 30 ms. Every bit of lead is delay between the shot and the sound. 0.12 is what the engine ships with and is safe on any machine; 0.05 takes 70 ms off and is fine when the game holds its frame rate; if you hear crackling, go back up.

Suggestions

Play a minute on each, then look at the telemetry page: it shows the game ping the server measured for you with each combination. The number that matters is that ping at a frame rate you are happy with.

The 2011 league config (an experiment)

What a CAL and ESEA player's userconfig.cfg did in 2011 — thirty-odd settings passed from hand to hand: a hundred updates and commands a second, interpolation pinned at 0.01, frames capped at 99.5, vsync off, the textures unfiltered, no shell casings, no smoke puffs, corpses gone at once, fog and dithering and overbright off, no detail textures. Most of it was about frame rate on a Pentium 4, and some of it about seeing an enemy through the noise. This applies the lot to the engine here, reads every value back to see which the engine took, and measures your frame rate for five seconds before and five after. Nothing in it changes your keys, your sensitivity or your name. Where this engine spells a setting differently (gl_texture_nearest for gl_texturemode) both are sent, so the list says which name it answered to.
